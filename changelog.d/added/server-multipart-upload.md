The HTTP server accepts a `multipart/form-data` request on `POST /pdf`, so a document can be sent together with the style sheets, images and fonts it refers to, without inlining them or opening local file access. The form follows Gotenberg's: every file is a part named `files` (the folder part of its name is dropped, so the HTML refers to `logo.png`, not `assets/logo.png`), the file named `index.html` is the document, and `header.html`, `footer.html` and `cover.html` are the page header, footer and cover (`--header-html`, `--footer-html`, `--cover`), and `user-style-sheet.css` is the user-origin style sheet (`--user-style-sheet`: stronger than the built-in styles, weaker than the document's own CSS). A part without a file name is an option, with the name and the allow list of the query keys; the query still works beside it, and `?stream=1` too. The files are written into a directory made for the request, which is the base directory and the only place the request may read (`../` and absolute paths are refused as on the CLI), and it is removed when the request ends. A file name that is empty, `..`, a Windows device name or contains `<>:"|?*`, a name sent twice (also differing only in case), a file outside a part named `files` and a missing or empty `index.html` are `400`, and a `multipart/*` type other than `form-data` is `415`. `--max-body-size` applies to the whole request, so raise it when sending images or fonts. A body with another `Content-Type` is still the HTML itself. ZIP archives are not accepted yet.
